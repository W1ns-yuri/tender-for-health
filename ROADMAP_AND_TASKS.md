## 🎯 1. Приоритетная задача: Закрытые тендеры по списку участников (Private / Whitelist Tenders)

### 📌 Бизнес-требование:
Возможность для Администратора объявить **закрытый тендер**, в котором могут участвовать исключительно выбранные проверенные компании (например, 5–10 аккредитованных поставщиков). Сторонние поставщики не должны видеть этот тендер в общем реестре, иметь доступ к его документации или возможность подать коммерческое предложение.

### 🛠 Архитектура реализации:

#### А. База данных (`schema.prisma`):
1. **Связующая модель приглашенных участников**:
```prisma
model TenderInvitation {
  id         String   @id @default(uuid())
  tenderId   String   @map("tender_id")
  tender     Tender   @relation(fields: [tenderId], references: [id], onDelete: Cascade)
  supplierId String   @map("supplier_id")
  supplier   Supplier @relation(fields: [supplierId], references: [id], onDelete: Cascade)
  invitedAt  DateTime @default(now()) @map("invited_at")
  hasViewed  Boolean  @default(false) @map("has_viewed")

  @@unique([tenderId, supplierId])
  @@map("tender_invitations")
}
```
2. **Поле видимости в `Tender`**:
   - Поле `visibility` со значениями `ACYK` (Публичный) и `YAPYK` (Закрытый по приглашению / Whitelist).

#### Б. Интерфейс создания тендера (`CreateTenderPage.jsx`):
- Переключатель: **«Тип доступа: Публичный открытый / Закрытый по списку»**.
- При выборе закрытого режима появляется мультиселект аккредитованных поставщиков:
  - Поиск по наименованию, ИНН, региону.
  - Быстрый фильтр: *«Выбрать проверенных поставщиков из категории тендера»* (например, 10 фармацевтических компаний с лицензией).
  - Бейджи выбранных компаний с возможностью быстрого удаления.

#### В. Контроль доступа на бэкенде (Security & RBAC):
- В `tenderController.js` (`getTenders`):
  - Для `ADMIN`: видны все тендеры (открытые и закрытые).
  - Для `SUPPLIER`:
    - Открытые (`visibility: 'ACYK'`).
    - Закрытые (`visibility: 'YAPYK'`) отдаются **ТОЛЬКО** тем поставщикам, чей `supplier.id` содержится в `TenderInvitation` для данного тендера.
- В `createOffer`:
  - Если тендер закрытый, сервер проверяет наличие `supplierId` в таблице приглашений. Если компании нет в списке — возвращается ошибка `403 Forbidden` (*«Вы не включены в перечень приглашенных участников закрытого тендера»*).

#### Г. Уведомления:
- В момент публикации закрытого тендера выбранные 10 компаний получают уведомление в Центр уведомлений (колокольчик):  
  *«Вам направлено персональное приглашение на участие в закрытом тендере №...»*.

## 📑 2. Модуль контрактов и исполнения (Contract Management)

### 📌 Текущее состояние:
Процедура заканчивается на этапе «Победитель объявлен» (`YENIJI_YGLAN_EDILDI`) в модуле оценки, а у поставщика появляется запись в «Мои победы».

### 🛠 Что требуется реализовать:
1. **Автоматическая генерация контракта**:
   - После утверждения протокола комиссии автоматически создается черновик контракта с реквизитами победителя, спецификациями и ценами лота.
2. **Реестр контрактов (`/contracts`)**:
   - Таблица контрактов с фильтрами по статусам:
     - `DRAFT` — Формирование проекта договора.
     - `SENT_TO_SUPPLIER` — На подписании у поставщика.
     - `ACTIVE` — Подписан, действует, ведется отгрузка.
     - `FULFILLED` — Поставка завершена, акты подписаны.
     - `TERMINATED` — Расторгнут.
3. **Прикрепление документов**:
   - Возможность загрузки скана подписанного договора с печатью и актов приема-передачи (форма ТОРГ-12 / накладные).

## 👥 10. Управление администраторами и сотрудниками (Admin & Staff Management)

### 📌 Бизнес-требование:
Сейчас в системе один статический профиль администратора (`admin`). При внедрении платформы в реальные организации (министерства, ЛПУ, закупочные комитеты) недопустимо, чтобы весь штат работал под одной общей учетной записью. Требуется полноценный модуль управления персоналом:
1. **Интерфейс управления администраторами (`/admin/users`)**:
   - Создание новых учетных записей сотрудников (ФИО, должность, рабочий телефон, email, отдел).
   - Редактирование личных данных, блокировка/деактивация доступа и сброс пароля.
2. **Ролевая модель внутри комитета (Fine-Grained RBAC)**:
   - `ADMIN` (Главный администратор / Председатель комитета) — полный доступ ко всем настройкам, модерации и утверждению протоколов.
   - `PURCHASING_SPECIALIST` (Специалист по закупкам) — создание черновиков тендеров, проверка комплектности лотов, работа со справочниками.
   - `COMMISSION_MEMBER` (Член тендерной комиссии) — доступ к вскрытию заявок, выставлению баллов и подписанию протокола оценки.
3. **Персональная ответственность**:
   - Каждое действие в системе привязывается к конкретному физическому лицу, а не к абстрактному `admin`.

## 📜 11. Сквозное комплексное логирование действий («Кто, где, когда, куда и зачем»)

### 📌 Бизнес-требование:
Для обеспечения прозрачности государственных и ведомственных медицинских закупок необходим полный аудит-трейл:
1. **Детальная фиксация каждого шага**:
   - **Кто**: ID, логин, ФИО и роль пользователя.
   - **Где**: IP-адрес, браузер (User-Agent), модуль/раздел платформы.
   - **Когда**: точное серверное время с миллисекундами (ISO UTC).
   - **Куда и зачем**: тип операции (`CREATE`, `UPDATE`, `DELETE`, `LOGIN`, `VIEW_OFFER`, `DOWNLOAD_DOC`, `VOTE_COMMISSION`), идентификатор сущности и наименование объекта.
2. **История изменений (Diff Audit)**:
   - При изменении цен, спецификаций лотов или протоколов сохранять снимок «было / стало» в формате JSON.
3. **Расширенный интерфейс аудита ([AdminLogs.jsx](file:///c:/Users/Yuri/Desktop/Tender%20for%20Helth/frontend/src/pages/AdminLogs.jsx))**:
   - Фильтрация по датам, пользователю, типу операции, критичности (`INFO`, `WARNING`, `DANGER`).
   - Экспорт журнала аудита в Excel / CSV для контролирующих органов.

## 📈 12. Интерактивный 5-шаговый трекер жизненного цикла тендера (Tender Stepper / Lifecycle Tracker)

### 📌 Бизнес-требование:
В карточке закупки и в общем реестре добавить наглядный визуальный прогресс-бар из 5 ключевых этапов, позволяющий сразу оценить текущий прогресс процедуры:
```
[1. Создание и публикация] ➔ [2. Прием и модерация заявок] ➔ [3. Вскрытие и оценка] ➔ [4. Протокол и победитель] ➔ [5. Контракт и исполнение]
```
1. **Шаг 1: Формирование и публикация (DRAFT ➔ ACYK)**:
   - Заполнение основных параметров, лотов, спецификаций и прикрепление документации.
   - Фиксация даты публикации и старта приема предложений.
2. **Шаг 2: Прием и модерация коммерческих предложений (ACYK)**:
   - Подача заявок поставщиками.
   - Проверка комплектности документов; возможность запроса уточнений / повторной отправки при выявлении технических ошибок в спецификациях.
   - Таймер обратного отсчета до дедлайна.
3. **Шаг 3: Вскрытие конвертов и процедура оценки (YAPYK ➔ BAHALANDYRYLDY)**:
   - Дедлайн завершен. Автоматическая блокировка приема новых предложений.
   - Рассмотрение предложений членами комиссии, сопоставление цен и проверка соответствия ТЗ.
4. **Шаг 4: Подведение итогов и объявление победителя (YENIJI_YGLAN_EDILDI)**:
   - Голосование комиссии, автоматическое определение наименьшей цены.
   - Формирование официального протокола, уведомления участникам и победителю.
5. **Шаг 5: Заключение контракта и контроль исполнения (CONTRACT & EXECUTION)**:
   - Генерация проекта договора с победителем.
   - Подписание скана с синей печатью, мониторинг графика поставки, закрывающие накладные/акты.
