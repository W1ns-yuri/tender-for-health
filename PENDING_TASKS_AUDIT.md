## 🚨 Приоритет 1: Критические разрывы бизнес-логики

### 1.1. Живая система уведомлений («Оживить» колокольчик)
* **Текущее состояние:**
  * В шапке сайта ([Header.jsx](file:///c:/Users/Yuri/Desktop/Tender%20for%20Helth/frontend/src/components/Header.jsx)) массив уведомлений `defaultNotifications` — это **статический захардкоженный список строк**.
  * В схеме базы данных ([schema.prisma](file:///c:/Users/Yuri/Desktop/Tender%20for%20Helth/backend/prisma/schema.prisma)) **отсутствует модель `Notification`**.
  * На бэкенде нет эндпоинтов для получения, отметки о прочтении и генерации событий.
  * Статус прочитанных уведомлений временно пишется в `localStorage`.
* **Что необходимо сделать:**
  1. **База данных (`schema.prisma`)**: создать модель `Notification`:
     ```prisma
     model Notification {
       id        String   @id @default(uuid())
       userId    String   @map("user_id")
       user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
       title     String
       message   String
       type      String   @default("INFO") // INFO | SUCCESS | WARNING | DANGER
       link      String?  // Ссылка для быстрого перехода (например: /tenders/abc-123)
       isRead    Boolean  @default(false) @map("is_read")
       createdAt DateTime @default(now()) @map("created_at")
       
       @@map("notifications")
     }
     ```
  2. **Бэкенд сервис и API (`backend/src/controllers/notificationController.js`)**:
     * `GET /api/notifications` — получение списка уведомлений текущего пользователя с пагинацией и количеством непрочитанных (`unreadCount`).
     * `PUT /api/notifications/:id/read` — отметка конкретного уведомления как прочитанного.
     * `PUT /api/notifications/read-all` — отметка всех уведомлений пользователя прочитанными.
     * Утилита `sendNotification({ userId, title, message, type, link })`.
  3. **События (триггеры) для автогенерации уведомлений**:
     * **Приглашение в закрытый тендер**: при публикации тендера с типом `YAPYK` отправлять уведомления всем приглашенным поставщикам (`TenderInvitedSupplier`).
     * **Подача коммерческого предложения**: при подаче заявки поставщиком уведомлять организатора/админа закупки.
     * **Модерация профиля поставщика**: при подтверждении (`VERIFIED`) или отклонении (`REJECTED`) аккредитации компании высылать уведомление поставщику с текстом причины.
     * **Итоги тендера**: при утверждении протокола победителю отправлять поздравление с суммой выигрыша, а остальным участникам — уведомление о завершении оценки.
  4. **Фронтенд**:
     * Заменить статический массив в [Header.jsx](file:///c:/Users/Yuri/Desktop/Tender%20for%20Helth/frontend/src/components/Header.jsx) на реальный запрос `API.get('/notifications')`.
     * Встроить периодический поллинг (раз в 45 сек) или Server-Sent Events (SSE).
     * Показывать всплывающий Toast в правом верхнем углу экрана при получении нового события.

### 1.3. Модуль контрактов и исполнения договоров (Contract Management)
* **Текущее состояние:**
  * Процесс закупки обрывается на моменте выбора победителя в модуле оценки (`EvaluationDetailsPage.jsx`).
  * У поставщика выигранные позиции просто складываются в список «Мои победы», но нет юридического этапа заключения договора и контроля поставки.
* **Что необходимо сделать:**
  1. **Модель `Contract` в Prisma**:
     ```prisma
     model Contract {
       id             String   @id @default(uuid())
       contractNumber String   @unique @map("contract_number")
       tenderId       String   @map("tender_id")
       tender         Tender   @relation(fields: [tenderId], references: [id], onDelete: Cascade)
       supplierId     String   @map("supplier_id")
       supplier       Supplier @relation(fields: [supplierId], references: [id], onDelete: Cascade)
       amount         Float
       currencyId     String   @map("currency_id")
       status         String   @default("DRAFT") // DRAFT | SIGNED | IN_FULFILLMENT | COMPLETED | CANCELLED
       signDeadline   DateTime? @map("sign_deadline")
       deliveryDeadline DateTime? @map("delivery_deadline")
       files          ContractFile[]
       createdAt      DateTime @default(now())
       updatedAt      DateTime @updatedAt
       @@map("contracts")
     }
     ```
  2. **Автогенерация проекта контракта**: при нажатии «Утвердить протокол» автоматически генерировать проект договора с реквизитами заказчика и победителя.
  3. **Интерфейс реестра договоров (`/contracts`)**:
     * Просмотр этапов исполнения (подписание, отгрузка, приемка).
     * Загрузка скана подписанного договора с синей печатью.
     * Загрузка закрывающих документов (товарно-транспортные накладные, акты выполненных работ / формы ТОРГ-12).
